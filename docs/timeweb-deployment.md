# Bakery Ops на Timeweb Cloud

Целевая ветка приложения — `main`. Перед каждым деплоем проверять выбранные ветку и полный SHA
в панели App Platform. При подключении Git по URL автодеплой недоступен: после push нужно
запустить сборку нужного коммита в панели. GitHub-подключение позволяет включить автодеплой.

## Сервисы

- App Platform, Dockerfile, 1 CPU / 2 ГБ RAM / 30 ГБ, Москва. Порт 3000, healthcheck `/api/health`.
- PostgreSQL 17, 1 CPU / 1 ГБ / 8 ГБ, Москва; ежедневные бэкапы, подключение по TLS-домену.
- S3 Standard, 10 ГБ, **приватный** бакет; фотографии доступны только владельцу через `/api/storage/…`.

Сборка создаёт `standalone`-приложение без `.env`, `.git` и тестов. Шрифт Manrope с кириллицей
находится в `src/app/fonts` вместе с лицензией OFL; Google Fonts во время сборки не вызывается.

## Настройки приложения

Значения хранить только в переменных App Platform и локальном gitignored-файле `.env.timeweb`.
В панели можно импортировать файл с именем `.env`. Не загружать исходный `.env` целиком:
в нём остаются настройки Neon и Vercel, а также ключи, которые серверу приложения не нужны.

Обязательные переменные:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@TLS_HOST:5432/default_db
DATABASE_CA_CERT="-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----"
AUTH_SECRET=
AUTH_TRUST_HOST=true
APP_PASSWORD=
STAFF_PASSWORD=
STORAGE_PROVIDER=s3
S3_ENDPOINT=https://s3.twcstorage.ru
S3_REGION=ru-1
S3_BUCKET=
S3_ACCESS_KEY_ID=
S3_SECRET_ACCESS_KEY=
IIKO_APP_ID=
IIKO_API_KEY=
IIKO_CLIENT_SECRET=
IIKO_SCHEDULER_ENABLED=0
CRON_SECRET=
APP_REVISION=FULL_GIT_SHA
```

`DATABASE_CA_CERT` — сертификат Timeweb из вкладки подключения БД. При его наличии клиент
проверяет цепочку сертификатов и TLS-домен; `rejectUnauthorized: false` не используется.
`APP_PASSWORD` и `STAFF_PASSWORD` вводит владелец в панели: Production Secrets Vercel не читаются обратно.

Для бота также нужны `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_ALLOWED_CHAT_IDS`.
Настройки распознавания переносятся без изменения провайдера и модели.

## Перенос данных

1. Убедиться, что `.env` указывает на исходный Neon, а `.env.timeweb` — на пустую новую БД и приватный S3.
2. На время финального переноса согласовать отсутствие правок в старой версии.
3. На Mac с работающим Docker выполнить `npm run migrate:timeweb`.

Скрипт открывает **read-only snapshot** исходной БД, сохраняет `pg_dump` с правами 0600
в `~/.codex/backups/bakery-ops/`, восстанавливает его одной транзакцией только в пустую БД,
сравнивает количество строк всех таблиц и копирует фотографии с проверкой SHA-256.
Исходную БД он не изменяет. В новой БД ссылки на фото становятся относительными `/api/storage/…`.
Повторный запуск на непустой целевой БД остановится до восстановления.

## Проверка и переключение

1. `/api/health` возвращает 200 только при успешном запросе к PostgreSQL. Ответ не содержит реквизитов БД.
2. Сверить SHA деплоя с `main`, открыть технический адрес и проверить вход владельца и сотрудника.
3. Проверить отчёты, ФОТ, смены, исходные фотографии, доступ сотрудников и синхронизацию iiko.
4. После принятия новой версии включить `IIKO_SCHEDULER_ENABLED=1` в Timeweb.
   Постоянный Node-сервер запускает синхронизацию ежедневно в 04:00 МСК, с тремя повторами через
   пять минут при временной ошибке. Планировщик включается только явной переменной окружения.
5. Обновить Telegram webhook на новый HTTPS-адрес только после проверки приёма запросов.
6. Проверить доступ с обычного Wi-Fi и мобильного интернета без VPN; затем выдать новый адрес сотрудникам
   или переключить собственный домен. Адрес `*.vercel.app` принадлежит Vercel и на Timeweb не переносится.

Передача исходников, сборка, проверка приложения и переключение пользователей — отдельные этапы.
Старую версию и её данные сохранять до подтверждения переноса. После переключения не продолжать
ручное редактирование старой БД: две независимые копии сами изменения не объединяют.
