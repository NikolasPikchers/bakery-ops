# Bakery Ops — вкладка «ФОТ» (фонд оплаты труда), v1

**Дата:** 2026-06-08
**Статус:** design approved → план
**Контекст:** Nikas Cafe, Плюшкино (point-1). Зарплаты платятся налом (мимо Т-Бизнес), поэтому в расходах их сейчас нет → чистая прибыль завышена. Цель — вести табель смен и считать ФОТ, учитывая его в прибыли.

## Цель

Вкладка «ФОТ» по месяцам: табель выходов сотрудников (2 группы — Пекарня и Кондитерка) + авто-расчёт ЗП за смену (база + премия от выручки дня). Месячный ФОТ попадает в расходы дашборда (категория `fot`), чтобы чистая прибыль была честной.

## Авто-график (2/2), опорная дата `2026-06-08`

- **Пекарня (бригады):** A работает в дни цикла 0–1, B — 2–3. `cyclePos = floor((date − anchor)/2) mod 2`; A при `cyclePos==0`, B при `==1`. (08–09 A, 10–11 B, 12–13 A, …)
- **Кондитеры (2/2 со сдвигом o):** работает, если `((date − anchor − o) mod 4) ∈ {0,1}`. Лена o=0 (08,09…), Оксана o=1 (09,10…), Лариса o=2 (10,11…). Отрицательный mod нормализуем в [0,3].
- **Кухня (Людмила):** Пн–Пт (`getUTCDay() ∈ 1..5`).

Авто-график детерминирован от опорной даты (предсказывает любой месяц). Ручные отклонения — через override (см. ниже).

## Эффективная отметка выхода

`present(employee, date) = override(employee, date) ?? autoSchedule(employee, date)`.
Override хранится **только** для изменённых вручную ячеек.

## Расчёт ЗП за смену (если present)

Берётся выручка Плюшкино за этот день из `Revenue` (point-1): `total = amount`, `pies = amount − confectionery` («пироги+прочее»).
- **confectioner** → 2500 (без премии).
- **kitchen** → 1500 (без премии).
- **baker** → 2300 + `bakerBonus(pies)`.
- **cashier** → 2100 + `cashierBonus(total, pies)`.

Премии — ступеньки (берётся наибольший подходящий порог; ниже минимума → 0):

`bakerBonus(pies)`: ≥42000→1200, ≥36000→1000, ≥31000→800, ≥26000→500, ≥23000→300, ≥22000→100, иначе 0.

`cashierBonus(total, pies)`: ≥71000→1200, ≥66000→1000, ≥61000→800, ≥56000→500, ≥51000→300; иначе если `pies ≥ 22000` → 100; иначе 0.

Если за день нет записи `Revenue` → total=pies=0 → премия 0 (база всё равно платится за смену).

## Архитектура и компоненты

### 1. Доменное ядро (чистое, без БД) — `src/lib/fot/`
- `bonus.ts` — `bakerBonus(pies)`, `cashierBonus(total, pies)` (шкалы-константы).
- `schedule.ts` — `autoPresent(emp, isoDate, anchor)`: бригадный 2/2, кондитерский 2/2-со-сдвигом, кухня Пн–Пт. `ANCHOR = '2026-06-08'`.
- `payroll.ts` — `dailyPay(emp, { total, pies })`: база по роли + премия. Чистые функции, покрыты тестами.

### 2. Сборка табеля — `src/lib/db/fot-repo.ts`
- `loadFot(prisma, month)`: грузит `Employee[]`, `Revenue[]` (point-1, месяц) → map по дате `{total,pies}`, `Attendance[]` (overrides, месяц). Возвращает по группам: для каждого сотрудника — массив дней `{date, present, pay}`, сумма смен и ЗП; плюс дневные итоги ФОТ и месячный итог. Дополнительно на сотрудника **Пекарни** — накопительные суммы для двух выплат: `payTo15` (Σ дни 1–15), `payAfter15` (Σ дни 16–конец), `payTotal` (= к концу месяца). Для Кондитерки — только `payTotal` (выплата раз в месяц).
- `computePayrollTotal(prisma, month): number` — месячный ФОТ (для дашборда). Реализуется поверх `loadFot` (единый источник правды).
- `setAttendance(prisma, employeeId, date, present)` — upsert override.

### 3. Схема Prisma
- `enum EmployeeGroup { bakery confectionery }`, `enum EmployeeRole { baker cashier kitchen confectioner }`.
- `model Employee { id, name, group, role, brigade String?, basePay Decimal(10,2), schedOffset Int @default(0), active Boolean @default(true), createdAt }`.
- `model Attendance { id, employeeId→Employee, date Date, present Boolean, createdAt, updatedAt, @@unique([employeeId,date]) }`.
- Сид ростера — `scripts/seed-employees.mts` (10 человек выше; идемпотентно по имени+группе).

### 4. Интеграция с дашбордом
- `loadDashboard` дополнительно вызывает `computePayrollTotal(prisma, month)` и **добавляет** его к расходам: `finance.expense += fot`, в `byCategory` прибавляется/создаётся срез `fot`, `profit = revenue − expense` (уже включает ФОТ), маржа пересчитывается. Источник — табель (не дублируем в Expense).

### 5. UI — `src/app/fot/`
- `page.tsx` (server): навигация по месяцам (как на дашборде/разбивке), две секции **Пекарня** и **Кондитерка**.
- Табель-матрица на секцию: строки — сотрудники (имя + роль/бригада), столбцы — дни месяца; ячейка — отметка **✓** (выход) / пусто (нет). Клик по ячейке переключает (сохраняется как override). Снизу: «ФОТ/день» и «Итого за месяц» по секции.
- **Пекарня** — справа на сотрудника три накопительные суммы (платят 2 раза/мес): **«к 15-му»** (1–15), **«2-я половина»** (16–конец) и **«за месяц»**. Внизу секции — итоги по этим трём колонкам (сколько выдать 15-го и в конце месяца).
- **Кондитерка** — справа на сотрудника только **«ЗП за месяц»** (выплата раз в месяц).
- `FotGrid.tsx` (client): клик → `POST /api/fot/attendance {employeeId,date,present}` → `router.refresh()`.
- `src/app/api/fot/attendance/route.ts` (auth, nodejs): валидирует, `setAttendance`.
- Навигация: пункт «ФОТ».

## Область / вне области

**В области:** табель 2 групп, авто-график 2/2 + ручные правки, расчёт ЗП с премиями, месячный ФОТ в расходах дашборда, навигация по месяцам, стартовый ростер 10 человек (Плюшкино).
**Вне области (v1):** UI добавления/удаления/переименования сотрудников (ростер сидится; правки — позже); изменение ставок/шкал из UI (в коде); Корица (у неё ФОТ отдельно/нет); история смены графиков сверх override.

## Обработка ошибок
- Нет `Revenue` за день → премии 0, база платится (если смена).
- Клик по ячейке без авторизации → 401.
- Неизвестный `employeeId`/невалидная дата → 400.

## Тестирование (Vitest, чистые функции)
- `bonus`: контрольные точки шкал пекаря и кассира (включая «100 от пирогов», границы 22к/51к/71к, ниже минимума → 0).
- `schedule`: бригады A/B на ряде дат от опоры; кондитеры Лена/Оксана/Лариса на 08–13.06; кухня будни/выходные.
- `payroll`: `dailyPay` для каждой роли (база + премия) на сэмпле выручки; кондитер/кухня без премии.
- `loadFot`/`computePayrollTotal` — на фейк-данных (employees+revenue+overrides): суммы по сотруднику/дню/месяцу, применение override поверх авто-графика.
