# Bakery Ops — Фаза 2: интеграция с Т-Бизнес, v1

**Дата:** 2026-06-08
**Статус:** design approved → реализовано (с пивотом, см. ниже)

> ## ⚠️ Обновление 2026-06-08: пивот с API на импорт файла выписки
> При первом реальном прогоне выяснилось, что **Mac Mini выходит в интернет через зарубежный IP
> (VPN, Новая Зеландия), а T-Bank блокирует иностранные IP** — API недостижим (ConnectTimeout ко
> всем хостам банка, включая публичный дев-портал). Решение (выбор пользователя): **импорт файла
> выписки** (CSV), который пользователь выгружает из ЛК и передаёт (Телеграм/`~/Downloads`).
> Переиспользованы без изменений: категоризация, идемпотентный импорт, схема, оркестратор.
> Изменения относительно исходного дизайна:
> - Вместо `tbank/client.ts` (API) — `tbank/parse-statement.ts` (парсер CSV Т-Бизнес; `;`, BOM, кавычки).
> - Вместо коллектора по launchd — CLI-скрипт `scripts/import-statement.mts` (`.zip`/`.csv`, `--dry`).
> - Дедуп `externalId = «номер счёта|номер платежа|дата|сумма»` (номер платежа не уникален на 100%).
> - Добавлено исключение переводов себе (вывод средств ИП, `OWNER_INNS` + «перевод собственных средств»).
> - Карточные покупки («отражение операции оплаты по карте») → продукты; ИНН поставщиков → `CATEGORY_BY_INN`.
> - Шпаргалка: `docs/tbusiness-import.md`. Выпущенный API-токен пока не используется (пригодится, если появится РФ-выход).
**Контекст:** Nikas Cafe, 2 точки (Плюшкино = point-1, Корица = point-2). Касса — iiko (выручка), денежные расходы — расчётный счёт Т-Бизнес. До сих пор расходы вносились вручную; цель Фазы 2 — автоматически импортировать их из банка.

## Цель

Тянуть исходящие операции по расчётному счёту Т-Бизнес → категоризировать в 6 категорий → писать в таблицу `Expense` идемпотентно → дашборд показывает чистую прибыль (выручка iiko − расходы Т-Бизнес) без ручного ввода.

## Бизнес-контекст (со слов владельца)

- **Плюшкино** — полноценная точка: аренда, налоги, ФОТ и все покупки идут по общей карте/счёту Т-Бизнес.
- **Корица** — берёт кондитерку на реализацию; раз в неделю присылает общую сумму продаж. Товар тоже покупается на ту же общую карту.
- Один поток расходов (одна карта/счёт). Разнесение «общих» продуктов по точкам — **сознательно отложено** (см. «Вне области v1»).

## Область v1

Импорт расходов из Т-Бизнес по расписанию (pull), с базовой авто-категоризацией и идемпотентностью. Все импортированные расходы привязываются к **Плюшкино (point-1)** — в режиме дашборда «Все» итоговая чистая прибыль корректна независимо от точки.

## Вне области v1 (отложено)

- Разнесение продуктов/расходов Корицы по точкам (логика аллокации).
- Вебхуки T-API (берём pull).
- UI для ручного переназначения категории/точки операции (быстрый фоллоу после того, как данные поедут).
- Импорт выручки (выручка остаётся из iiko/ручная; Корица — недельная сумма вручную).

## Подход

**Pull выписки по расписанию**, не вебхук. Pull не требует публичного HTTPS-эндпоинта и конфликтующих с IP-allowlist egress-IP Vercel; ложится на существующий паттерн коллектора на Mac Mini (фикс. IP). Вебхук рассмотрим в будущем, если понадобится near-real-time.

## Архитектура и компоненты

Разбивка на изолированные модули с одной ответственностью:

### 1. `src/lib/tbank/client.ts` — клиент T-API (изолированный)
- Авторизация: `Authorization: Bearer ${TBUSINESS_API_TOKEN}`.
- `getAccounts(): Promise<BankAccount[]>` — список счетов компании.
- `getStatement(accountNumber, from, till): Promise<BankOperation[]>` — операции за период с курсорной пагинацией (до 5000/запрос; курсор из последней строки ответа передаётся в следующий запрос до исчерпания).
- **Единственное место**, где захардкожены: базовый host, пути endpoint'ов и маппинг сырого JSON → нормализованный `BankOperation`. Точные имена полей финализируются на первом реальном ответе.
- Нормализованный тип:
  ```ts
  type BankOperation = {
    id: string;            // уникальный ID операции (для дедупа)
    date: string;          // ISO yyyy-mm-dd
    amount: number;        // абсолютная сумма, ₽
    direction: 'in' | 'out';
    counterparty: string | null;
    inn: string | null;
    purpose: string | null; // назначение платежа
  };
  ```
- Сетевые вызовы с явным timeout; ошибка/не-2xx → throw (без тихих фолбэков).

### 2. `src/lib/tbank/categorize.ts` — категоризация (чистая функция, TDD)
- `categorize(op: BankOperation): { category: ExpenseCategoryKey; needsReview: boolean }`.
- Правила по приоритету (регистронезависимо, по `purpose` + `counterparty`):
  - «аренд» → `arenda`
  - «налог» / «ндфл» / «страхов взнос» / «фнс» / «казначейств» → `nalogi`
  - «зарплат» / «заработн» / «аванс» / «фот» → `fot`
  - «электро» / «энерго» / «водоснаб» / «тепло» / «газ» / «коммунал» / «связь» / «интернет» → `kommunalka`
  - ИНН из списка поставщиков продуктов (`PRODUCT_SUPPLIER_INNS`, изначально пуст, расширяется) → `produkty`
  - иначе → `prochee`, `needsReview: true`
- `needsReview` помечает операции, попавшие в `prochee` по умолчанию (кандидаты на ручную докатегоризацию в будущем UI). Хранится косвенно: операции с `category = prochee` и `source = tbusiness` = очередь на проверку.

### 3. `src/lib/tbank/import-expenses.ts` — оркестратор
- Вход: `prisma`, окно дат (по умолчанию последние ~35 дней).
- Шаги: `getStatement` → фильтр `direction === 'out'` → `categorize` → **идемпотентный upsert** в `Expense` по `externalId`.
- Возвращает сводку: `{ fetched, imported, updated, skipped }` для лога коллектора.
- Идемпотентность: повторный прогон того же окна не плодит дубликаты (upsert по `externalId`); правки суммы/назначения в банке подтягиваются (update).

### 4. Миграция схемы Prisma
- `enum ExpenseSource { manual import tbusiness }` — добавить `tbusiness`.
- `model Expense`: добавить
  - `externalId String? @unique` — ID банковской операции (дедуп). Nullable: ручные записи остаются с `null` (Postgres допускает несколько NULL при unique).
  - `counterparty String?`
  - `inn String?`
  - назначение платежа пишем в существующее поле `note`.
- `pointId` остаётся обязательным; импортёр всегда ставит point-1.
- DDL применяется на `DATABASE_URL_UNPOOLED` (см. конвенции проекта).

### 5. Коллектор + launchd
- `scripts/collect-tbusiness.mts` — точка входа: грузит `.env`, создаёт `PrismaClient` (driver adapter), вызывает `import-expenses`, печатает сводку, выходит.
- launchd-plist на Mac Mini, запуск раз в сутки (напр. 04:00), по образцу Salary Radar collector; логи в файл.
- Env: `TBUSINESS_API_TOKEN`, `DATABASE_URL` (+ `DATABASE_URL_UNPOOLED` для миграций), опц. `TBUSINESS_ACCOUNT` (если счетов несколько — иначе берём первый/единственный).

## Поток данных

```
launchd (Mac Mini, 04:00)
  └─ collect-tbusiness.mts
       └─ import-expenses(prisma, last 35d)
            ├─ tbank.client.getStatement(acc, from, till)   [Bearer, пагинация]
            ├─ filter direction == 'out'
            ├─ categorize(op)                                 [чистая, по правилам]
            └─ prisma.expense.upsert by externalId            [Neon]
                 → Expense(source=tbusiness, pointId=point-1, category, externalId, counterparty, inn, note=purpose)
  ⇒ дашборд (Vercel) читает Expense → чистая прибыль / структура расходов
```

## Обработка ошибок

- Нет `TBUSINESS_API_TOKEN` → коллектор падает с понятной ошибкой (не тихо).
- Не-2xx / таймаут T-API → throw, ненулевой exit-код (launchd залогирует; следующий прогон подхватит окно заново — идемпотентно).
- Пустая выписка → сводка с нулями, exit 0.
- Неизвестная категория → `prochee` + needsReview, не теряем операцию.

## Тестирование

- `categorize` — юнит-тесты на реальных формулировках назначений (TDD): аренда, налоги, зарплата, коммуналка, поставщик по ИНН, прочее.
- `client` маппинг — тест на захваченном сэмпле JSON (без PII; синтетический/обезличенный).
- `import-expenses` — тест с замоканным клиентом: фильтр исходящих, идемпотентность (двойной прогон), корректный upsert.
- Существующие тесты финансов/дашборда не ломаются (source `tbusiness` проходит как расход).

## Валидация на первом реальном прогоне

После появления токена в `.env`: один прогон коллектора в debug-режиме печатает **ключи** сырого объекта операции (не значения/не PII) → финализируем маппинг полей в `client.ts` → прогоняем полноценно. Точные имена JSON-полей официального T-API — единственная внешняя неизвестность, и она изолирована в одном модуле.
