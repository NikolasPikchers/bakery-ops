# Расходы из Т-Бизнеса

С 17.11.2026 расходы приходят **автоматически через T-API**: сервис работает на Timeweb в России,
и банк его пускает (раньше сервис ходил через зарубежный VPN, а T-Bank такие IP блокирует — отсюда
импорт файлов ниже, он остался запасным путём).
Выручка сюда НЕ попадает (она из iiko); из выписки берём только **расходы** (исходящие операции).
Все импортированные расходы → **Плюшкино (point-1)** (разнесение по точкам — отдельная задача).

## Автоматически (T-API)

- **Каждую ночь** в 04:00 МСК вместе с iiko (`src/instrumentation.ts` → `runNightlySync`):
  последние **7 дней** — банк проводит часть операций (карты, комиссии) с опозданием.
- **Кнопкой** «Обновить из банка» на странице «Расходы»; там же — свой период до 93 дней.
- По `CRON_SECRET`: `GET /api/cron/tbank-sync?from=ГГГГ-ММ-ДД&till=ГГГГ-ММ-ДД[&dry=1]`
  (`dry=1` — посчитать без записи). Диагностика полей: `GET /api/cron/tbank-diagnose?from=&till=`.

### Токен
- `TBUSINESS_API_TOKEN` — в `.env.timeweb` и в переменных приложения на Timeweb. Выпускается в ЛК
  Т-Бизнеса → «Интеграции»; права — только чтение (выписка, список счетов).
- Токен **привязан к IP сервера `5.42.123.140`** (исходящий IP приложения Timeweb, сверен по
  `pg_stat_activity`). С Mac запросы к банку не пройдут. Если приложение на Timeweb пересоздать,
  IP сменится — нужен новый токен (изменить IP у токена нельзя). Живёт 90 дней с последнего использования.
- Сертификат `business.tbank.ru` выпущен НУЦ Минцифры: доверие к нему добавлено только в запросах
  к банку (`src/lib/tbank/https-fetch.ts`, `russian-ca.ts`; промежуточный сертификат — до 06.03.2027).

### Как сопоставляются операции
- Сверено на проде 25–31.10.2026, 79 из 79: `documentNumber` = «Номер платежа»,
  `operationDate` = дата, `accountAmount` = сумма, `payPurpose` = назначение (категории совпали).
- Ключ расхода — «счёт|номер платежа|дата|сумма». Из файла он записан как `…|31.10.2026|406,7`,
  из API — `…|2026-10-31|406.70`; `src/lib/tbank/expense-key.ts` сравнивает канонический вид, поэтому
  операция из файла при синхронизации **обновляется**, а не дублируется, и наоборот.
- Переводы себе: ИНН владельца/назначение (как в файле) + категория банка `self*`.
- Категорию при обновлении не трогаем — ручные правки на «Расходах» сохраняются.

## Вручную: файл выписки (запасной путь)


1. С устройства, которое видит ЛК Т-Бизнес (телефон/ноут на росс. сети), выгрузи **выписку по счёту**
   за нужный период. Формат — CSV (банк отдаёт `.zip` с `.csv` внутри; подойдёт и распакованный `.csv`).
2. Перенеси файл на Mac Mini (Телеграм-бот / AirDrop / `~/Downloads`).
3. Предпросмотр без записи в БД (увидеть разбивку по категориям):
   ```
   cd ~/bakery-ops
   npm run import:statement -- "/путь/к/Выписка.zip" --dry
   ```
4. Импорт:
   ```
   npm run import:statement -- "/путь/к/Выписка.zip"
   ```
   Вывод: `{ fetched, outgoing, imported, updated }`. Идемпотентно — повторный импорт того же
   периода ничего не дублирует (дедуп по `externalId = счёт|номер платежа|дата|сумма`),
   а изменения суммы/назначения подтянет.

## Категоризация

Логика в `src/lib/tbank/categorize.ts`:
- **Исключаются** переводы себе на счёт (вывод средств ИП): `OWNER_INNS` + назначение «перевод собственных средств».
- **Продукты**: покупки по бизнес-карте («Отражение операции оплаты по карте …») + ИНН поставщиков из `CATEGORY_BY_INN`.
- **Аренда / Налоги / ФОТ / Коммуналка**: по ключевым словам (`RULES`) и ИНН.
- Банковские/эквайринговые комиссии → **Прочее**.
- Остальное → **Прочее** с пометкой needsReview (кандидаты на ручную докатегоризацию).

### Как уточнить категории
- Новый поставщик продуктов / арендодатель → добавить его **ИНН** в `CATEGORY_BY_INN`.
- Новое ключевое слово → в соответствующий `RULES`.
- После правок повторить импорт (идемпотентно перезапишет категории).

## Заметки
- ФОТ (зарплаты) через этот счёт не проходят — выплачиваются налом из переводов себе. При появлении
  безналичных выплат зарплаты добавить правило/ИНН.
- Чтобы дашборд показывал чистую прибыль, нужна выручка из iiko (вносится отдельно).
